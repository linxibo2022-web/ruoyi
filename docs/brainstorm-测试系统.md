# 头脑风暴：测试系统方案

**创建时间**: 2026-08-09 04:27
**最后更新**: 2026-08-09 04:27
**状态**: 已确定方案

## 背景与目标

为 erp_sys 项目建立测试体系，在 PR 创建后自动执行 CI，测试不通过则拦截合并。

核心原则：**后端 + 前端全覆盖，CI 门禁自动化。放弃的只是复杂页面的定制 E2E 脚本，框架本身全要。**

### 术语约定

| 术语 | 含义 | 本次方案中 |
|------|------|-----------|
| **冒烟测试** | 快速跑一遍核心流程，验证"基本链路没断"。过了才值得往下测 | 第 3 层 Playwright CRUD 模板脚本（TC-01~08） |
| **单元测试** | 测单个函数/方法的正确性，不依赖外部环境 | 第 1 层后端 JUnit + 第 2 层前端 Vitest |
| **E2E 测试** | 端到端，模拟真实用户在浏览器里操作完整页面 | 第 3 层 Playwright |

---

## 方案讨论

### 最终选定：全面覆盖，放弃复杂页面定制

- **要的**: 后端单元测试 + 前端 Vitest + 前端 Playwright（标准 CRUD）+ CI 门禁
- **放弃的**: 非标准 CRUD 复杂页面的定制 Playwright 脚本（代价大、数量少、不值得）

---

## 最终结论

### 测试金字塔（执行顺序）

```
        ┌──────────────┐
        │  冒烟测试     │  ← 第一步，2-3 分钟
        │  Playwright   │     CRUD 页面 TC-01~08
        │  (8 个用例)   │     挂了直接拦截，不往下跑
        └──────┬───────┘
               │ 通过 ✅
        ┌──────┴───────┐
        │  深度测试     │  ← 第二步，分钟级
        │  Vitest       │     前端 utils/composables 单元测试
        │  JUnit        │     后端 Service 单元测试
        └──────┬───────┘
               │ 通过 ✅
        ┌──────┴───────┐
        │  手工验证     │  ← 最后兜底
        │  复杂页面     │     非标页面人工走一遍
        └──────────────┘
```

### 四层测试体系

```
第 0 层：CI 门禁（PR 触发，全自动）
├── 后端: mvn test
├── 前端: pnpm vitest
├── 前端: pnpm playwright test
└── 任何失败 → 拦截合并

第 1 层：后端单元测试（JUnit5 + ruoyi-common-test）
├── 基类: BaseUnitTest / BaseServiceTest / BaseControllerTest
├── 工具: TestDataBuilder
├── 命令: mvn test
└── 目标: 80% 核心 Service 逻辑覆盖

第 2 层：前端单元测试（Vitest）
├── 测: utils / composables / store 核心函数
├── 命令: pnpm vitest
└── 目标: 80% 核心函数覆盖

第 3 层：冒烟测试 — 前端 E2E（Playwright）
├── 标准 CRUD 页面: 通用模板脚本（TC-01~08 配方，传参数即可复用）
├── 复杂非 CRUD 页面: ❌ 放弃，不写定制脚本
├── 命令: pnpm playwright test
└── 详细用例见下方「冒烟测试配方」

### 冒烟测试配方（TC-01 ~ TC-08）

> 来源：`e2e-test-pc` 技能沉淀。所有 CRUD 页面结构一致，这一套配方通用。
> 每次跑完约 2-3 分钟，验证核心链路是否通。

| 编号 | 用例 | 做什么 | 断言什么 |
|:---:|------|------|------|
| TC-01 | 页面加载 | 打开菜单页，等表格出现 | 表格存在；API 200；控制台无 error |
| TC-02 | 列表渲染 | 检查首行数据和分页 | 数据非空；字典列已翻译成中文；分页计数正确 |
| TC-03 | 新增 | 点新增 → 填必填 → 提交 | toast 提示成功；弹窗关闭；行数 +1 |
| TC-04 | 搜索 | 搜索框输入关键词 | 结果行含关键词；API 带正确查询参数 |
| TC-05 | 编辑 | 点行内修改 → 弹窗回显 → 改值 → 提交 | 列表对应行显示新值 |
| TC-06 | 删除 | 点删除 → 确认 → 提交 | toast 成功；行数 -1（清理 TC-03 造的数据） |
| TC-07 | 表单校验 | 新增弹窗 → 必填留空 → 点提交 | 校验报错阻止提交；弹窗仍在 |
| TC-08 | 分页 | 点下一页 | API 带 pageNum=2；数据变化 |

**五维断言**：每个用例同时检查 ①UI可见性 ②数据正确性 ③接口健康 ④无JS报错 ⑤交互闭环。缺一不算通过。
```

### 资源盘点

| 层次 | 资源 | 当前状态 | 要做什么 |
|------|------|:---:|------|
| 后端测试 | `ruoyi-common-test` 四个基类 | ✅ 就绪 | 按模块批量写测试方法 |
| 后端 CI | `mvn test` | ✅ 就绪 | CI 配置文件里加一行 |
| 前端 Vitest | `vitest` + `@vue/test-utils` | ⚠️ 需引入 | `pnpm add` + 配置 + 写用例 |
| 前端 Playwright | `@playwright/test` | ⚠️ 需引入 | `pnpm add` + 配置 + CRUD 模板脚本 |
| CRUD E2E 配方 | `e2e-test-pc` 技能 TC-01~08 | ✅ 流程已有 | 翻译为 Playwright 参数化脚本 |
| CI 文件 | `.gitlab-ci.yml` | ⚠️ 需创建 | 编排三步测试命令 |

### 放弃范围（明确）

| 放弃项 | 原因 |
|--------|------|
| 复杂非 CRUD 页面的定制 Playwright 脚本 | 每个页面单独分析、写选择器、处理交互，代价大；非标页面本身少，不值得建体系 |

### 实施步骤

1. [ ] **引入 Vitest** — `pnpm add -D vitest @vue/test-utils jsdom`，加 `vitest.config.ts`
2. [ ] **引入 Playwright** — `pnpm add -D @playwright/test`，加 `playwright.config.ts`，`pnpm exec playwright install`
3. [ ] **CRUD E2E 模板脚本** — 将 e2e-test-pc 的 TC-01~08 翻译为 Playwright 参数化脚本
4. [ ] **CI 配置文件** — 根目录加 `.gitlab-ci.yml`，编排：后端 test → Vitest → Playwright
5. [ ] **后端单元测试补写** — 逐个核心模块补 Service 层测试
6. [ ] **前端单元测试补写** — 核心 utils/composables/store 覆盖
7. [ ] **模板固化** — 稳定后新项目 clone 即用

## 风险与注意事项

| 风险 | 应对策略 |
|------|---------|
| 后端测试用例量大、写起来耗时 | 按模块优先级逐个补，先核心后边缘 |
| Vitest/Playwright 首次引入有学习成本 | 先跑通一个示例，再按模板复制 |
| 复杂页面无 E2E 覆盖 | 复杂页面本身少，后端逻辑测试 + 手工验收兜底 |
| CI 运行时间过长 | 后端和前端测试可并行执行 |
