## 计划契约头

- **执行模式**：`dev-loop`
- **判定依据**：用户确认“先生成执行计划”，但未要求自动执行、`plan-executor`、并行子 Agent 或一次完成整个计划；因此本计划默认按依赖顺序逐项执行和回写，不声明可自动跑完整个计划。
- **目标**：让主代理每次创建 Claude Code/Codex 子代理前，针对具体子任务重新进行技能评估，并以可信、紧凑、可审计的信封传递结果；同时完成项目 agent 的跨端单源生成、风险门禁、上下文预算和安全迁移。
- **架构**：技能触发继续由 `.agent-governance/skills-manifest.json` 与现有 router 管理；项目 agent 元数据、风险级别和跨端能力引用由新增 `agents-manifest.json` 管理。公共 preflight、信封、registry 和启动上下文位于 `.agent-governance/lib/`，Claude/Codex Hook 仅做运行时字段适配。
- **技术栈**：Node.js CommonJS、JSON manifest/fixture、Claude Code hooks 与 agent Markdown、Codex hooks 与 agent TOML、现有同步/校验脚本。
- **模块归属**：Agent 治理基础设施；不属于业务模块。
- **端支持**：Claude Code、Codex。
- **数据库/表前缀**：不涉及。
- **非目标**：不修改业务代码、数据库、前后端页面；首版不实现强制 `selectAgent()`；不承诺多代理降低总 Token；Codex 递归深度未被真实运行时证明前不宣称硬门禁。
- **上位需求说明**：仓库当前不存在 `docs/需求文档.md`，本计划以已确认的 brainstorm 文档和当前仓库事实作为上位契约。

### 全局成功标准

1. 主会话原有 `UserPromptSubmit` 技能路由行为、44 个现有双端 fixture 和安全 Hook 不回归。
2. Claude `Agent.prompt` 与 Codex `spawn_agent.message` 均在创建前得到独立的任务级路由结果。
3. `matched`、`no-match`、`router-error`、`invalid-input` 可区分；只有通用只读探索可在错误时降级，高风险角色必须 deny。
4. 伪造、重复、截断或正文中的 `SUBAGENT_SKILL_ROUTE` 标记不能绕过权威重算。
5. `check` 在 Claude 解析为 Command、在 Codex 解析为 Skill；Claude Command 不进入 agent `skills:`。
6. Claude 递归委派真实 deny；Codex 依据 P0 探针结论选择硬门禁或可审计软约束，不伪造能力。
7. 新项目角色为 `ruoyi-code-reviewer`、`ruoyi-project-reporter`、`ruoyi-project-updater`；内置保留名不被覆盖。
8. 双端 agent 由同一治理源生成；运行时发现目录不会同时保留新旧项目角色。
9. Hook、agent、信封与回传摘要满足上下文预算，日志和审计不保存任务正文。
10. 全部静态门禁、双端 Hook 测试、staging 验收和无交互运行时验收通过后才能完成任务；不能自动观测的能力必须在报告中以 `unsupported` 或 `not-observable` 固化，不能等待人工确认。

### 初始上下文预算

| 项目 | 初始上限 | 说明 |
|---|---:|---|
| 单个技能路由信封 | 1024 UTF-8 字节 | `updatedInput` 中的任务原文不计入信封体积 |
| `SubagentStart.additionalContext` | 800 tokens | 与 `additionalContextLimit` 语义一致，另记录 UTF-8 字节数 |
| 单个中立 agent 正文 | 200 行 | 禁止复制技能全文和大型检查清单 |
| Claude 静态预载技能 | 0～2 个，合计不超过 8 KiB | 仅 `preloadable: true` 的 Skill；Command 不预载 |
| 子代理单次回传摘要 | 1500 个中文字符以内 | 只含结论、证据路径、风险和验证结果 |

P0 实测若证明某项预算不可行，可在不扩大主线程污染的前提下调整；必须记录基线、理由和新上限，不能静默放宽。

- **执行顺序修正**：最小 `agents-manifest`/registry 前移到 preflight 前，因为风险分级与 `SubagentStart` 都依赖角色元数据；P3 只负责补全中立正文与生成器。
