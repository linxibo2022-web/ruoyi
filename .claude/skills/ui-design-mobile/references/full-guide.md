
# 移动端页面设计指南

> **设计哲学**：简洁 · 大气 · 专业
>
> 简洁不是简单，而是恰到好处的克制。
> 大气不是空旷，而是有节奏的呼吸感。
> 专业不是复杂，而是细节处的用心。

---

## 核心设计原则

### 「简洁」的标准

| 维度 | 简洁 | 繁杂 |
|------|------|------|
| **信息密度** | 一屏只说一件事 | 一屏塞满所有内容 |
| **视觉元素** | 必要的图标和文字 | 装饰性图标、复杂背景 |
| **颜色使用** | 主色 + 辅色 + 中性色 | 五颜六色 |
| **操作路径** | 3步内完成核心任务 | 层层嵌套、复杂流程 |
| **组件选择** | 标准组件、统一样式 | 花哨动效、非标准交互 |

**简洁的检验标准**：能删的都删了吗？删掉后影响理解吗？

### 「大气」的标准

| 维度 | 大气 | 局促 |
|------|------|------|
| **留白** | 内容周围有充足呼吸空间 | 元素紧贴边缘和彼此 |
| **间距** | 统一的间距系统（8的倍数） | 随意的间距、参差不齐 |
| **字号** | 清晰可读、层次分明 | 字小密集、层次模糊 |
| **卡片** | 舒适的内边距、圆角 | 内容撑满、无呼吸感 |
| **图片** | 高质量、统一比例 | 模糊、比例混乱 |

**大气的检验标准**：眯眼看页面，是否有舒适的节奏感？

### 「专业」的标准

| 维度 | 专业 | 业余 |
|------|------|------|
| **对齐** | 严格的栅格对齐 | 对齐混乱、视觉跳跃 |
| **一致性** | 相同功能相同样式 | 同类组件样式不一 |
| **状态反馈** | 加载、空状态、错误都有设计 | 只考虑正常状态 |
| **细节** | 图标风格统一、圆角一致 | 图标混搭、圆角随意 |
| **交互** | 响应迅速、反馈清晰 | 无反馈、操作迟滞 |

**专业的检验标准**：用户会觉得这是大公司做的吗？

## 间距系统（核心）

### 8px 基准网格

所有间距必须是 **8rpx 的倍数**（特殊情况可用 4rpx）：

```scss
/* 标准间距变量 */
$spacing-xs: 8rpx;    /* 极小：图标与文字 */
$spacing-sm: 16rpx;   /* 小：紧凑元素间 */
$spacing-md: 24rpx;   /* 中：常规元素间 */
$spacing-lg: 32rpx;   /* 大：区块间 */
$spacing-xl: 48rpx;   /* 超大：页面区域间 */
$spacing-xxl: 64rpx;  /* 巨大：重要分隔 */
```

### 常用间距场景

| 场景 | 间距 | 示例 |
|------|------|------|
| 页面边距 | `32rpx` | `padding: 0 32rpx;` |
| 卡片内边距 | `24rpx` | `padding: 24rpx;` |
| 列表项间距 | `16rpx` | `margin-bottom: 16rpx;` |
| 图标与文字 | `8rpx` | `margin-left: 8rpx;` |
| 标题与内容 | `16rpx` | `margin-top: 16rpx;` |
| 区块间距 | `32rpx ~ 48rpx` | `margin-bottom: 48rpx;` |
| 底部安全区 | `env(safe-area-inset-bottom)` | 固定底部按钮必须 |

### 间距原则

```
┌─────────────────────────────────────┐
│ ← 32rpx →                 ← 32rpx → │  页面边距
│  ┌─────────────────────────────┐    │
│  │ ← 24rpx →         ← 24rpx → │    │  卡片内边距
│  │                             │    │
│  │  标题                       │    │
│  │  ↓ 16rpx                    │    │  标题与内容
│  │  内容文字                   │    │
│  │                             │    │
│  └─────────────────────────────┘    │
│              ↓ 16rpx                │  卡片间距
│  ┌─────────────────────────────┐    │
│  │  ...                        │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

## 颜色策略

### 语义化配色

```scss
/* 主色 - 品牌识别 */
$color-primary: #4080FF;      /* 主操作、链接、强调 */
$color-primary-light: #E8F3FF; /* 主色浅底 */

/* 功能色 - 状态反馈 */
$color-success: #00B42A;      /* 成功、完成、正常 */
$color-warning: #FF7D00;      /* 警告、提醒 */
$color-danger: #F53F3F;       /* 错误、危险、删除 */
$color-info: #86909C;         /* 信息、次要 */

/* 中性色 - 文字与背景 */
$color-text-primary: #1D2129;   /* 主要文字 */
$color-text-regular: #4E5969;   /* 常规文字 */
$color-text-secondary: #86909C; /* 次要文字 */
$color-text-disabled: #C9CDD4;  /* 禁用文字 */

$color-bg-page: #F7F8FA;        /* 页面背景 */
$color-bg-card: #FFFFFF;        /* 卡片背景 */
$color-border: #E5E6EB;         /* 边框颜色 */
```

### 配色原则

1. **60-30-10 法则**
   - 60% 中性色（背景、卡片）
   - 30% 辅助色（文字、边框）
   - 10% 强调色（按钮、链接）

2. **颜色不要超过 3 种**
   - 主色系 1 种
   - 功能色按需使用
   - 中性色不算

3. **避免纯黑 #000000**
   - 使用 `#1D2129` 或 `var(--wd-color-title)`
   - 纯黑对比太强，不够柔和

## 字体规范

### 字号层级

```scss
/* 字号系统（rpx） */
$font-size-xs: 20rpx;    /* 辅助说明、标签 */
$font-size-sm: 24rpx;    /* 次要文字 */
$font-size-md: 28rpx;    /* 正文（默认） */
$font-size-lg: 32rpx;    /* 小标题 */
$font-size-xl: 36rpx;    /* 标题 */
$font-size-xxl: 44rpx;   /* 大标题 */
$font-size-huge: 56rpx;  /* 数字强调 */
```

### 字重使用

| 场景 | 字重 | CSS |
|------|------|-----|
| 大标题、数字 | 加粗 | `font-weight: 600;` |
| 小标题、按钮 | 中等 | `font-weight: 500;` |
| 正文、说明 | 常规 | `font-weight: 400;` |

### 行高规范

```scss
/* 行高 = 字号 + 8~12rpx */
.text-xs { font-size: 20rpx; line-height: 28rpx; }
.text-sm { font-size: 24rpx; line-height: 32rpx; }
.text-md { font-size: 28rpx; line-height: 40rpx; }
.text-lg { font-size: 32rpx; line-height: 44rpx; }
```

## 页面布局模式

### 模式一：列表页（最常用）

```
┌─────────────────────────────┐
│  🔍 搜索栏                   │ ← 可选
├─────────────────────────────┤
│  筛选标签 | 排序              │ ← 可选
├─────────────────────────────┤
│                             │
│  ┌───────────────────────┐  │
│  │  列表项 1              │  │
│  └───────────────────────┘  │
│         ↓ 16rpx             │
│  ┌───────────────────────┐  │
│  │  列表项 2              │  │
│  └───────────────────────┘  │
│         ↓ 16rpx             │
│  ┌───────────────────────┐  │
│  │  列表项 3              │  │
│  └───────────────────────┘  │
│                             │
```

**设计要点**：
- 使用 `wd-paging` 组件
- 列表项使用 `wd-cell` 或自定义卡片
- 保持列表项高度一致
- 空状态使用 `wd-status-tip`

## 组件选型指南

### 什么时候用什么组件

| 需求场景 | 推荐组件 | 不推荐 |
|---------|---------|--------|
| 单行信息展示 | `wd-cell` | 自定义 view |
| 分组列表 | `wd-cell-group` | 多个独立 cell |
| 卡片容器 | `wd-card` | 自定义 view + 样式 |
| 导航跳转列表 | `wd-cell` + `is-link` | 按钮 |
| 图标入口 | `wd-grid` | 自定义 flex 布局 |
| 标签页切换 | `wd-tabs` | 自定义按钮组 |
| 筛选条件 | `wd-drop-menu` | 自定义弹窗 |
| 状态标签 | `wd-tag` | 自定义样式文字 |
| 空状态 | `wd-status-tip` | 自定义空状态 |
| 加载更多 | `wd-paging` / `wd-loadmore` | 自定义分页 |

### 按钮使用原则

```vue
<!-- 主操作：实心主色 -->
<wd-button type="primary">立即购买</wd-button>

<!-- 次操作：线框或浅色 -->
<wd-button plain>加入购物车</wd-button>

<!-- 危险操作：红色警示 -->
<wd-button type="error">删除</wd-button>

<!-- 辅助操作：文字按钮 -->
<wd-button type="text">取消</wd-button>
```

**按钮排列**：主操作在右/下，次操作在左/上

## 状态设计（必须考虑）

### 每个页面必须设计的状态

| 状态 | 组件 | 说明 |
|------|------|------|
| 加载中 | `wd-skeleton` / `wd-loading` | 首次加载时展示 |
| 空数据 | `wd-status-tip type="search"` | 列表无数据 |
| 网络错误 | `wd-status-tip type="network"` | 请求失败 |
| 无权限 | `wd-status-tip type="permission"` | 权限不足 |
| 操作中 | `wd-button loading` | 提交等待 |

### 空状态设计示例

```vue
<template #empty>
  <wd-status-tip
    type="search"
    tip="暂无相关数据"
  >
    <template #bottom>
      <wd-button size="small" @click="refresh">刷新试试</wd-button>
    </template>
  </wd-status-tip>
</template>
```

## 反面案例（避免踩坑）

### 1. 信息过载

```vue
<!-- ❌ 错误：一个卡片塞太多信息 -->
<view class="card">
  <image src="..." />
  <text>标题</text>
  <text>副标题</text>
  <text>描述描述描述...</text>
  <text>¥99.00</text>
  <text>原价 ¥199.00</text>
  <text>销量 1234</text>
  <text>库存 100</text>
  <text>已售罄</text>
  <view>标签1</view>
  <view>标签2</view>
  <view>标签3</view>
  <button>购买</button>
  <button>收藏</button>
  <button>分享</button>
</view>

<!-- ✅ 正确：精简信息、分层展示 -->
<view class="card">
  <image src="..." mode="aspectFill" />
  <view class="content">
    <text class="title">商品标题</text>
    <view class="price-row">
      <text class="price">¥99.00</text>
      <text class="sold">已售 1234</text>
    </view>
  </view>
</view>
```

### 2. 间距混乱

```scss
/* ❌ 错误：随意的间距 */
.card1 { margin-bottom: 15rpx; }
.card2 { margin-bottom: 20rpx; }
.card3 { margin-bottom: 12rpx; }

/* ✅ 正确：统一的间距系统 */
.card { margin-bottom: 16rpx; }  /* 8的倍数 */
```

### 3. 颜色过多

```scss
/* ❌ 错误：五颜六色 */
.tag-1 { background: #FF6B6B; }
.tag-2 { background: #4ECDC4; }
.tag-3 { background: #45B7D1; }
.tag-4 { background: #96CEB4; }
.tag-5 { background: #FFEAA7; }

/* ✅ 正确：语义化配色 */
.tag-success { background: var(--wd-color-success); }
.tag-warning { background: var(--wd-color-warning); }
.tag-danger { background: var(--wd-color-danger); }
```

### 4. 没有留白

```vue
<!-- ❌ 错误：内容撑满 -->
<view class="card" style="padding: 0;">
  <text>内容紧贴边缘</text>
</view>

<!-- ✅ 正确：合理留白 -->
<view class="card" style="padding: 24rpx;">
  <text>内容有呼吸空间</text>
</view>
```

### 5. 忽略状态设计

```vue
<!-- ❌ 错误：只考虑正常情况 -->
<view v-for="item in list">{{ item.name }}</view>

<!-- ✅ 正确：考虑所有状态 -->
<wd-skeleton v-if="loading" />
<wd-status-tip v-else-if="!list.length" type="search" tip="暂无数据" />
<view v-else v-for="item in list">{{ item.name }}</view>
```

## 设计检查清单

在完成页面设计后，对照检查：

### 简洁性检查

- [ ] 每屏信息是否聚焦一个主题？
- [ ] 能删除的元素是否都删了？
- [ ] 颜色是否控制在 3 种以内？
- [ ] 没有纯装饰性元素？

### 大气感检查

- [ ] 页面边距是否统一（32rpx）？
- [ ] 元素间距是否遵循 8rpx 倍数？
- [ ] 卡片内边距是否足够（24rpx）？
- [ ] 文字行高是否舒适？

### 专业度检查

- [ ] 元素是否严格对齐？
- [ ] 相同功能样式是否一致？
- [ ] 空状态/加载状态是否设计？
- [ ] 图标风格是否统一？
- [ ] 圆角大小是否一致？

## 🔗 关联技能边界

本技能专注于**设计思维**（视觉布局、留白、间距、色彩、信息层级）。遇到以下场景请改用其他技能：

| 场景 | 应使用技能 | 判断关键词 |
|------|-----------|-----------|
| 具体组件怎么用（wd-form、wd-popup） | `ui-mobile` | "wd-"、"组件用法"、"API" |
| plus-app 原生项目的独有差异 | `app-adapter` | "plus-app"、"原生插件"、"鸿蒙" |
| HTML 设计稿转 Vue 代码 | `html-to-code` | "HTML 转代码"、"设计稿" |

**三技能分工**：
- `ui-design-mobile` = **设计层**（审美、排版、留白）
- `ui-mobile` = **技术层**（组件 API 用法）
- `app-adapter` = **项目层**（plus-app 项目差异）

**协作链路**：先 `ui-design-mobile` 确定布局 → 再 `ui-mobile` 选对组件 → plus-app 项目再查 `app-adapter`。
