# /sync - 同步项目文档

一键同步三个项目管理文档的数据一致性。自动创建缺失文档，确保所有文档数据统一。

---

## 适用场景

- 长时间未更新文档，需要全量同步
- 怀疑三个文档数据不一致
- 手动编辑过文档后需要同步
- 项目交接或新成员加入时了解现状

---

## 第一步：检查并创建缺失文档

### 检查文档状态

```
docs/
├── 项目状态.md    ← 检查是否存在
├── 待办清单.md    ← 检查是否存在
└── 需求文档.md    ← 检查是否存在
```

### 自动创建缺失文档

对于每个缺失的文档：
1. 读取对应模板 `.claude/templates/*.md`
2. 扫描代码获取初始数据
3. 创建文档
4. 记录创建操作

---

## 第二步：扫描代码获取真实状态（Source of Truth）

### 2.1 扫描业务模块

**扫描范围**（只扫描业务代码）：
- `ruoyi-modules/ruoyi-*`（排除 common/admin/extend/system/generator）
- `plus-ui/src/views/`（排除 system/tool/common）
- `plus-uniapp/src/pages-sub/`

**检查完整性**：
```
每个功能模块检查以下文件：
- Entity.java
- Bo.java
- Vo.java
- Controller.java
- IService.java
- ServiceImpl.java
- IDao.java
- DaoImpl.java
- Mapper.java

完整度 = 存在的文件数 / 9 * 100%
```

### 2.2 扫描 Git 提交

- 获取最近 20 条提交
- 识别业务相关提交（feat/fix/update/add）
- 提取功能名称和完成日期
- 计算各功能的开发耗时

### 2.3 扫描 TODO/FIXME

**扫描业务代码中的标记**：
```
// TODO: xxx      → 中优先级待办
// FIXME: xxx     → 高优先级待办
// XXX: xxx       → 需关注
// OPTIMIZE: xxx  → 低优先级优化
// HACK: xxx      → 技术债务
```

**记录信息**：
- 完整文件路径
- 行号
- 标记内容
- 所属模块

---

## 第三步：同步项目状态.md

### 3.1 更新"已完成"区域

**数据来源**：
- 代码中完整度为 100% 的功能模块
- Git 提交中带有 feat/add 的功能

**同步规则**：
- 如果代码中存在完整功能，但文档中未记录 → 添加
- 如果文档中记录为"进行中"，但代码已完整 → 移到"已完成"
- 保留文档中的手动描述和备注

### 3.2 更新"进行中"区域

**数据来源**：
- 代码完整度在 1%-99% 的功能

**同步规则**：
- 更新进度百分比
- 记录缺失的文件

### 3.3 更新"待办"区域

**数据来源**：
- 代码中的 TODO/FIXME 标记
- 待办清单.md 中的高优先级任务

---

## 第四步：同步待办清单.md

### 4.1 同步已完成任务

**规则**：
- 项目状态.md 中标记完成的任务 → 移到"最近完成"
- 代码中 TODO 已删除的 → 移到"最近完成"

### 4.2 同步新增待办

**规则**：
- 代码中新增的 TODO → 添加到对应优先级
- 去重：检查是否已存在相同或相似任务

### 4.3 清理无效待办

**规则**：
- 对应代码文件已删除的 TODO → 标记为"已失效"或移除
- 超过 30 天未处理的低优先级 → 提示归档

### 4.4 更新统计信息

```markdown
## 📊 统计信息
- 待办总数: X 项
- 高优先级: X 项
- 中优先级: X 项
- 低优先级: X 项
- 本周新增: X 项
- 本周完成: X 项
```

---

## 第五步：同步需求文档.md

### 5.1 同步需求状态

**规则**：
- 项目状态.md 中标记完成的功能 → 对应需求标记"已完成"
- 进行中的功能 → 对应需求标记"开发中"

### 5.2 更新技术信息

**从 pom.xml 提取**：
- Java 版本
- Spring Boot 版本
- 关键依赖版本

---

## 第六步：冲突检测与处理

### 检测规则

| 冲突类型 | 检测方式 | 处理方式 |
|---------|---------|---------|
| 状态不一致 | 同一任务在不同文档状态不同 | 以代码为准，提示用户 |
| 重复任务 | 相同或相似任务多次出现 | 合并，保留更详细的描述 |
| 孤立记录 | 文档中记录的功能代码中不存在 | 标记为"待确认"，提示用户 |
| 时间冲突 | 完成日期与 Git 记录不符 | 以 Git 为准 |

### 冲突报告

```markdown
## ⚠️ 检测到以下冲突

### 状态不一致
- "用户管理模块"
  - 项目状态.md: 进行中
  - 代码完整度: 100%
  - **建议**: 更新为已完成

### 孤立记录
- "短信通知功能"
  - 文档中: 存在
  - 代码中: 未找到
  - **建议**: 确认是否已删除或改名
```

## 与其他命令的关系

| 命令 | 说明 |
|------|------|
| `/update-status` | 增量更新，适合日常使用 |
| `/sync` | 全量同步，适合定期整理或发现不一致时使用 |
| `/init-docs` | 首次初始化，选择模式 |
| `/progress` | 只读查看，不修改文档 |

---

## 使用建议

| 场景 | 建议命令 |
|------|---------|
| 日常开发完成功能后 | `/update-status` |
| 每周五整理项目状态 | `/sync` |
| 发现数据不一致 | `/sync` |
| 首次使用项目管理 | `/init-docs` → `/sync` |
| 快速查看进度 | `/progress` |
