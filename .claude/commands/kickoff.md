# /kickoff - 从一句话想法到自主循环开发（RuoYi-Plus-UniApp 前门编排器）

在框架模板里一句话起一个新业务项目：**联网调研出需求 → 工作站出原型 → 孵化新项目 → 起飞自主循环**。
每个产出都有人工门，你点头才往下——**前段你把关「做什么」，后段交给 `/dev-loop` 自主做「怎么做」**。

> **关键节奏**：前段（需求 + 原型）**只产文档和原型、绝不碰代码**；改 Maven 坐标/标识符/端口/DB/前端标识这些，**等到第三步「创建新项目」(`project-init` 孵化) 才做**。🔴 Java 包名 `plus.ruoyi` 全程不改。
> **无 Logo 环节**（按需可后续单独走工作站 /logo）。

## 用法

```
/kickoff <一句话项目想法>
```
例：`/kickoff 做一个社区团购：PC 后台 + 小程序端`

## 总原则

- **前 2 段交互、有人工门**，AI 不闷头冲；最后才进自主循环。
- **全程复用现成件**，不重复造：原型走【工作站 ui-studio】+ 框架 `html-to-code`、孵化走 `project-init`、循环走 `dev-loop`、CRUD 走 `/dev`。
- 产出物先落在**模板框架**的 `docs/需求文档.md`、`docs/prototypes/`，由 `project-init` 孵化时带入新项目。
- **反捏造**：调研结论标来源；不确定标「待确认」。本框架是商业产品，事实以项目档案 + 用户原话为准。

---

## 阶段一　需求孵化（联网 + 头脑风暴）→ 🚦人工门

1. **联网调研**：用 `WebSearch` 查同类业务 / 方案 / 合规与风险；必要时调【工作站】`/research`（ai-workstation MCP → research-studio）。
2. **头脑风暴**：把想法扩成结构化需求——目标、核心场景、功能范围与**边界**、优先级、路线图（MVP→V1→V2）。**对接 RuoYi 概念**：哪些是新业务模块（建表 + CRUD）、要挂哪些菜单/权限/数据字典。
3. **产出需求**：写到 `docs/需求文档.md`（或调框架 `/init-docs` 初始化业务文档体系）。**不碰任何代码/坐标。**
4. 🚦**人工门**：把「调研要点 + 完善建议 + 需求摘要」给用户，**停下等确认 / 修改**。通过才进阶段二。

## 阶段二　原型生成（必须走工作站）→ 🚦人工门

1. 按确认的需求，**调【AI 工作站】生成原型**：ai-workstation MCP → `route`（query=按需求做 PC 后台 / 移动端 UI 原型）→ `get_skill`(ai-ui-studio) → 产出到 `docs/prototypes/<业务>/*.html`（带「组件映射表」注释：PC 对应 plus-ui 封装组件、移动端对应 plus-uniapp WD 组件）。
   - 🔴 **禁止模型自己手搓 HTML 充当原型**；一律走工作站 ui-studio（保证可被 `html-to-code` 转码 + `dev-loop` 截图闭环逐元素对照）。
2. 🚦**人工门**：把原型给用户看，**停下等确认 / 修改**。**仍不碰代码。** 通过才进阶段三。

## 阶段三　创建新项目（= project-init 孵化，这一步才改标识符）

- **执行 `project-init` 技能**（框架自带，已极成熟）。到这一步才：选分支 + 选保留的前端/移动端（plus-ui/plus-uniapp/plus-app）→ 复制模板出新目录 → 改 Maven 坐标/标识符/端口/DB 库名/前端标识 → 建私有仓库 → 建库导数据。
- 🔴 **Java 包名 `plus.ruoyi` 不动。**
- 把 `docs/需求文档.md` + `docs/prototypes/` 带入新项目（随复制；如需"剪切回归基线"按 project-init 流程）。
- 按 `project-init` 交互流程走，**不在本命令里重复它的逻辑**。

## 阶段四　起飞（交给 dev-loop）

- 由 `project-init` 的「Step 5.2」输出 `/loop /dev-loop` 起飞指令。
- 到新项目里新开 Claude Code 粘 `/loop /dev-loop`：第 0 轮按需求+原型自拆 `docs/tasks/active/` 任务台账；之后每轮一个最小单元，CRUD 走 `/dev`、原型转码走 `html-to-code`、后端 `mvn` / 前端 build 验证、UI 走截图闭环、每轮更新任务台账 + 规范 commit，里程碑调 `/update-status` 汇总三文档，直到做完。

---

## 约束

- 本命令在【框架模板】运行，**可用 ai-workstation MCP**。
- **每个人工门必须真的停下等用户**；前段绝不碰代码/坐标。
- 产出 UTF-8 无 BOM；不按名杀宿主进程；本地提交不推远端（除非明确要求）；仓库私有。

## 与相邻能力的边界

| 能力 | 角色 |
|------|------|
| **/kickoff**（本命令） | 前门编排：研究→需求门→原型门→孵化→起飞（无 Logo） |
| 工作站 `/ui`（MCP）/ `html-to-code` | 原型生成 / 原型转码 |
| `project-init` 技能 | 孵化引擎（复制模板+改标识符+建仓库+建库，**不改包名**） |
| `/dev` | CRUD 代码生成器（dev-loop 加模块时复用） |
| `dev-loop` 命令 | 起飞后的自主循环（编排既有技能 + 截图闭环 + tasks/active + update-status 汇总） |
