# /add-test — 为已有模块补充测试

## 用途

为已存在的业务模块自动生成测试文件。支持三种场景：

1. **全量补充**：模块没有任何测试，一次性生成 ServiceTest + ControllerTest + E2E + Vitest（按需）
2. **增量补充**：模块已有部分测试，补充缺失的（如用户后来写了 composable，现在补 Vitest）
3. **单类型补充**：只补某一种测试（如"只加 E2E 配置"）

## 调用方式

```
/add-test [模块名]              # 自动检测并补充全部缺失测试
/add-test [模块名] --vitest     # 仅检测并补充 Vitest
/add-test [模块名] --e2e        # 仅追加 E2E 配置
/add-test [模块名] --backend    # 仅补充后端测试
```

## 执行流程

### 第一步：定位模块信息

通过模块名找到对应代码：

```
1. 搜索 Service: ruoyi-business/.../service/I{模块名}Service.java
2. 提取: 包路径、Class名、模块名(base/mall/crm/iot)、API路径前缀
3. 搜索前端: plus-ui/src/api/business/[module]/{模块名}/
```

### 第二步：扫描已有测试（去重）

```
检查:
- ruoyi-admin/src/test/.../service/{Class}ServiceTest.java
- ruoyi-admin/src/test/.../controller/{Class}ControllerTest.java
- plus-ui/src/__tests__/e2e/crud-smoke.spec.ts 中 CRUD_PAGES 数组
- plus-ui/src/__tests__/composables/use{Module}.test.ts
- plus-ui/src/__tests__/utils/{module}.test.ts

结果:
- 缺失的 → 生成
- 已有且含 @Generated → 跳过
- 已有但无标记 → 提示用户确认是否覆盖
```

### 🔴 Vitest 智能检测规则（V1~V5）

```
执行检测:

V1: plus-ui/src/composables/use{Module}.ts 存在？
    → 存在 → 生成 use{Module}.test.ts

V2: plus-ui/src/utils/{module}.ts 存在且有 export function？
    → 是 → 为每个 export 函数生成 describe 块

V3: plus-ui/src/store/modules/{module}.ts 存在且有非通用 action？
    → 是 → 生成 {module}Store.test.ts（只测自定义 action）

V4: {Class}ServiceImpl.java 方法数 > 6？
    → 是 → 在 ServiceTest 中追加"自定义业务逻辑"测试段
    → 否 → 标准 CRUD，不需要额外测试

V5: .vue 文件 computed 数量 ≥ 3？
    → 是 → 打印: "⚠️ {功能名}.vue 有 N 个 computed，建议提取为 composable: use{Module}.ts，然后 /add-test --vitest 补测"
    → 不自动生成（需人工先重构）

全部不满足：
    → 打印: "⏭️ 跳过 Vitest（标准 CRUD，无自定义逻辑需要测试）"
```

## 防护规则

1. **@Generated 标记**：所有自动生成的测试文件第一行含标记注释，再次执行时检测标记行跳过去重
2. **E2E 去重**：`apiAdd` 字段唯一性校验
3. **不自动覆盖**：文件存在但无 @Generated 标记 → 提示用户确认
4. **不自动 git add**：生成后提示跑通后手动提交
