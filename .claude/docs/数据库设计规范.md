# 数据库设计规范

> **⚠️ 重要提醒**: 本项目是 **ruoyi-plus-uniapp** 框架，数据库设计必须遵循项目规范！
> **请参考现有业务表**（如 `b_ad` 广告表）学习设计规范，而不是参考其他框架！

## 表命名规范

**新业务表的SQL语句必须存放在**: `script/sql/ry_plus_new.sql`

| 表类型 | 前缀 | 示例 |
|--------|------|------|
| **系统表** | `sys_` | `sys_user`, `sys_role` |
| **基础业务表** | `b_` | `b_ad`, `b_bind` |
| **商城模块表** | `m_` | `m_goods`, `m_order` |

## 数据类型规范

| 业务场景 | 数据库类型 | Java类型 | 示例 |
|----------|------------|----------|------|
| **主键ID** | `BIGINT(20)` | `Long` | `user_id BIGINT(20)` |
| **状态标识** | `CHAR(1)` | `String` | `status CHAR(1) DEFAULT '1'` |
| **短文本** | `VARCHAR(30-100)` | `String` | `user_name VARCHAR(30)` |
| **长文本** | `VARCHAR(255-500)` | `String` | `remark VARCHAR(500)` |
| **超长文本** | `TEXT` | `String` | `content TEXT` |
| **金额** | `DECIMAL(10,2)` | `BigDecimal` | `price DECIMAL(10,2)` |
| **时间** | `DATETIME` | `Date` | `create_time DATETIME` |

## 布尔值规范

- **状态字段** (`status`): `1`=正常(积极), `0`=停用(消极)
- **删除标记** (`is_deleted`): `0`=正常, `1`=已删除
- **是否字段** (`is_xxx`): `1`=是, `0`=否

## 主键设计

> **重要**: 本项目使用 **雪花ID**（ASSIGN_ID），不是自增ID！

### MyBatis-Plus 全局配置

```yaml
# ruoyi-common/ruoyi-common-mybatis/src/main/resources/common-mybatis.yml
mybatis-plus:
  global-config:
    dbConfig:
      # 主键类型: ASSIGN_ID 雪花算法
      idType: ASSIGN_ID
```

### 数据库表设计

```sql
-- ✅ 正确：不使用 AUTO_INCREMENT
id BIGINT(20) NOT NULL COMMENT '主键ID',

-- ❌ 错误：使用自增
id BIGINT(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
```

### Entity 主键注解

```java
// ✅ 正确：只指定字段名，使用全局配置的雪花ID
@TableId(value = "id")
private Long id;

// ❌ 错误：显式指定自增类型
@TableId(value = "id", type = IdType.AUTO)
private Long id;
```

## 审计字段 (必备字段)

```sql
CREATE TABLE business_table (
    id          BIGINT(20)   NOT NULL COMMENT '主键ID',  -- 雪花ID，不用 AUTO_INCREMENT
    -- 业务字段
    name        VARCHAR(100) NOT NULL COMMENT '名称',
    -- 审计字段
    create_dept BIGINT(20)   DEFAULT NULL COMMENT '创建部门',
    create_by   BIGINT(20)   DEFAULT NULL COMMENT '创建者',
    create_time DATETIME     COMMENT '创建时间',
    update_by   BIGINT(20)   DEFAULT NULL COMMENT '更新者',
    update_time DATETIME     COMMENT '更新时间',
    -- 逻辑删除字段
    is_deleted  CHAR(1)      DEFAULT '0' COMMENT '是否删除',
    PRIMARY KEY (id)
) ENGINE=InnoDB COMMENT='业务表';
```

## 索引设计

```sql
CREATE TABLE sys_user (
    user_id     BIGINT(20)   NOT NULL COMMENT '用户ID',
    user_name   VARCHAR(30)  DEFAULT NULL COMMENT '用户账号', 
    dept_id     BIGINT(20)   DEFAULT NULL COMMENT '部门ID',
    status      CHAR(1)      DEFAULT '1' COMMENT '状态',
    email       VARCHAR(50)  DEFAULT '' COMMENT '邮箱',
    create_time DATETIME     COMMENT '创建时间',
    is_deleted  CHAR(1)      DEFAULT '0' COMMENT '是否删除',
    
    -- 索引设计
    PRIMARY KEY (user_id),                           -- 主键索引
    UNIQUE KEY uk_user_name (user_name),             -- 用户名唯一索引
    UNIQUE KEY uk_email (email),                     -- 邮箱唯一索引
    KEY idx_dept_id (dept_id),                       -- 部门ID索引
    KEY idx_status (status),                         -- 状态索引
    KEY idx_create_time (create_time),               -- 创建时间索引
    KEY idx_status_deleted (status, is_deleted)      -- 复合索引
) ENGINE=InnoDB COMMENT='用户信息表';
```

## 索引设计原则

- 主键必建: 每张表必须有主键索引
- 外键建索引: 外键字段建议添加索引
- 频繁查询建索引: WHERE条件中的字段
- 唯一性约束: 业务上唯一的字段建唯一索引
- 复合索引遵循最左前缀原则: (a,b,c) 支持 (a), (a,b), (a,b,c)

## 字典设计规范

### 字典使用场景
当字段有**固定的几个可选值**时,应使用字典管理:
- ✅ 状态字段: 启用/停用 (1, 0)
- ✅ 类型字段: 类型A/类型B/类型C
- ✅ 性别字段: 男/女/未知
- ❌ 不适合: 用户输入的自由文本

### 新增字典类型

**1. 插入字典类型** (sys_dict_type 表):

```sql
-- 示例: 广告类型字典
INSERT INTO sys_dict_type
VALUES (100, '000000', '广告类型', 'b_ad_type', '0', '1', 100, 1,
        sysdate(), null, null, '广告类型列表');
```

**字段说明**:
- `dict_id`: 字典类型ID (自定义唯一值,建议从100开始)
- `tenant_id`: 租户ID (默认 '000000')
- `dict_name`: 字典名称 (中文,用于显示)
- `dict_type`: 字典类型编码 (英文,表前缀+字段名,如 `b_ad_type`)
- `is_system`: 是否系统字典 (0=业务字典, 1=系统字典)
- `status`: 状态 (1=正常, 0=停用)

**2. 插入字典数据** (sys_dict_data 表):

```sql
-- 示例: 广告类型的具体选项
INSERT INTO sys_dict_data
VALUES (1001, '000000', 1, '横幅广告', 'banner', 'b_ad_type', '', 'primary', '0', '1',
        100, 1, sysdate(), null, null, '横幅广告');

INSERT INTO sys_dict_data
VALUES (1002, '000000', 2, '视频广告', 'video', 'b_ad_type', '', 'success', '0', '1',
        100, 1, sysdate(), null, null, '视频广告');
```

**字段说明**:
- `dict_data_id`: 字典数据ID (唯一值,建议从1001开始)
- `dict_sort`: 排序值 (越小越靠前)
- `dict_label`: 显示标签 (中文,前端显示用)
- `dict_value`: 存储值 (英文/数字,数据库存储用)
- `dict_type`: 所属字典类型 (对应 sys_dict_type.dict_type)
- `list_class`: 回显样式 (primary/success/warning/danger/info)
- `is_default`: 是否默认值 (1=是, 0=否)

### 字典值小写规范 ⭐⭐⭐⭐⭐

> **⚠️ 重要**: 字典值（`dict_value`）必须是**小写英文字母或数字**，禁止使用大写字母！

**规则说明**:
- **字符串类型**: 必须使用小写英文字母 (如 `banner`, `pending`, `coupon`)
- **数字类型**: 使用纯数字 (如 `1`, `2`, `3`)
- **禁止**: 大写字母 (`BANNER`)、混合大小写 (`Banner`)、驼峰命名 (`camelCase`)

**为什么必须小写**:
1. **数据库规范**: 字典值直接存储在数据库中，小写保持一致性
2. **前端枚举**: 前端代码中会直接使用字典值作为常量
3. **API 传输**: 字典值在接口中传输，小写更符合 RESTful 规范
4. **可读性**: 小写字母在日志和调试中更易读

**正确示例** ✅:

| 字典标签 (dict_label) | 字典值 (dict_value) | 说明 |
|---------------------|-------------------|------|
| 横幅广告 | `banner` | ✅ 小写 |
| 视频广告 | `video` | ✅ 小写 |
| 待处理 | `pending` | ✅ 小写 |
| 已处理 | `processed` | ✅ 小写 |
| 优惠券 | `coupon` | ✅ 小写 |
| 正常 | `1` | ✅ 数字 |
| 停用 | `0` | ✅ 数字 |

**错误示例** ❌:

| 字典标签 (dict_label) | 字典值 (dict_value) | 问题 |
|---------------------|-------------------|------|
| 横幅广告 | `BANNER` | ❌ 全大写（禁止！） |
| 视频广告 | `VIDEO` | ❌ 全大写（禁止！） |
| 待处理 | `PENDING` | ❌ 全大写（禁止！） |
| 优惠券 | `Coupon` | ❌ 首字母大写（禁止！） |
| 已处理 | `Processed` | ❌ 首字母大写（禁止！） |
| 反馈类型 | `feedbackType` | ❌ 驼峰命名（禁止！） |
| 广告位置 | `Ad_Position` | ❌ 混合命名（禁止！） |

### 字典命名规范

| 字典类型 | 命名规则 | 示例 |
|---------|---------|------|
| **系统字典** | `sys_` + 功能名 | `sys_user_gender`, `sys_enable_status` |
| **业务字典** | 表前缀 + 字段名 | `b_ad_type`, `m_order_status` |

## 设计检查清单

**表设计检查:**
- 命名规范: 表名、字段名遵循命名规范
- 主键设计: 每张表都有主键
- 审计字段: 包含完整的审计字段
- 逻辑删除: 添加 is_deleted 字段
- 数据类型: 选择合适的数据类型和长度
- 字段注释: 每个字段都有清晰的注释
- 字典配置: 固定选项的字段是否配置了字典

**索引设计检查:**
- 主键索引: 主键字段有索引
- 外键索引: 外键字段建议添加索引
- 唯一索引: 唯一性约束字段添加唯一索引
- 查询索引: 频繁查询字段添加索引
