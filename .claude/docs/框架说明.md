## 🎯 业务开发区域（需要开发的地方）

### 后端业务模块位置

```
ruoyi-modules/
├── ruoyi-system/          ❌ 框架模块（不要修改）
├── ruoyi-generator/       ❌ 框架模块（不要修改）
└── ruoyi-{你的业务}/      ✅ 创建你的业务模块（示例：ruoyi-mall、ruoyi-iot、ruoyi-crm）
```

**创建业务模块的标准结构**：

```
ruoyi-modules/ruoyi-mall/          # 示例：商城模块
├── pom.xml
└── src/main/java/plus/ruoyi/mall/
    ├── controller/                # 控制器
    ├── service/                   # 服务接口
    │   └── impl/                  # 服务实现
    ├── dao/                       # 数据访问接口
    │   └── impl/                  # 数据访问实现
    ├── mapper/                    # MyBatis Mapper
    └── domain/                    # 领域对象
        ├── bo/                    # 业务对象
        └── vo/                    # 视图对象
```

**或者多业务域结构**：

```
ruoyi-modules/ruoyi-business/      # 基础业务模块
└── src/main/java/plus/ruoyi/business/
    ├── base/                      # 基础功能域
    │   ├── controller/
    │   ├── service/
    │   ├── dao/
    │   └── domain/
    ├── crm/                       # CRM 业务域
    │   ├── controller/
    │   └── ...
    └── iot/                       # IoT 业务域
        ├── controller/
        └── ...
```

### 前端业务页面位置（PC端）

```
plus-ui/src/views/
├── system/                        ❌ 框架页面（系统管理）
├── tool/                          ❌ 框架页面（工具页面）
├── common/                        ❌ 框架页面（通用页面）
├── business/                      ✅ 业务页面（基础业务）
├── mall/                          ✅ 业务页面（商城模块）
├── iot/                           ✅ 业务页面（IoT模块）
├── crm/                           ✅ 业务页面（CRM模块）

**规则**：
- ❌ **框架目录**：只有 `system/`、`tool/`、`common/`

```
plus-ui/src/views/

│   ├── goods.vue                  # 商品管理
│   └── order.vue                  # 订单管理
└── crm/                           # CRM业务页面
    └── customer.vue               # 客户管理
```

**示例 2：business 目录结构**
```
plus-ui/src/views/
└── business/                      # 基础业务目录
    ├── base/                      # base 子模块
    │   └── ad.vue                 # 广告管理
    └── platform/                  # platform 子模块
        └── config.vue             # 平台配置
```

### 移动端业务页面位置

```
plus-uniapp/src/
├── pages/                         ⚠️ 混合（框架主包 + 业务主包）
│   ├── index/                     ❌ 框架（首页）
│   ├── login/                     ❌ 框架（登录）
│   ├── user/                      ❌ 框架（个人中心）
│   └── goods/                     ✅ 业务（商品主包页面，如果有）
└── pages-sub/                     ✅ 业务（分包页面，全部是业务）
    └── {模块名}/
        └── {页面名}.vue
```

**规则**：
- ❌ **框架主包页面**：`pages/index`、`pages/login`、`pages/user`
- ✅ **业务主包页面**：`pages/` 下除了上述 3 个目录外的都可能是业务
- ✅ **业务分包页面**：`pages-sub/` 下全部是业务页面

**示例**：
```
plus-uniapp/src/
├── pages/
│   ├── index/                     ❌ 框架（首页）
│   ├── login/                     ❌ 框架（登录）
│   ├── user/                      ❌ 框架（个人中心）
│   └── home/                      ✅ 业务（商城首页，主包）
└── pages-sub/
    ├── mall/                      ✅ 业务（商城分包）
    │   ├── goods.vue
    │   └── order.vue
    └── device/                    ✅ 业务（设备管理分包）

## 📏 进度统计规则

### 核心原则：使用排除法（黑名单）

**为什么用排除法？**
- ✅ **灵活**：用户可以创建任意名称的业务目录
- ✅ **准确**：不会遗漏用户的自定义业务模块
- ✅ **简单**：只需维护一个小的框架模块排除列表

**对比说明**：
```
❌ 错误做法（白名单）：只统计 business/、mall/、iot/
   问题：如果用户创建了 crm/、erp/、product/ 等目录，会被遗漏

✅ 正确做法（黑名单）：只排除 system/、tool/、common/
   好处：用户创建任何业务目录都会被自动识别
```

---

### 只统计业务模块

**后端**：
- ✅ 统计：`ruoyi-modules/ruoyi-*`（排除 ruoyi-system、ruoyi-generator）
- ❌ 不统计：ruoyi-common、ruoyi-admin、ruoyi-extend、ruoyi-system、ruoyi-generator

**前端 PC - Views**：
- ✅ 统计：`plus-ui/src/views/*`（排除 system、tool、common）
- ❌ 不统计：system、tool、common
- 📝 说明：business/、mall/、iot/、crm/、erp/、product/ 等**所有非框架目录都统计**

**前端 PC - API**：
- ✅ 统计：`plus-ui/src/api/*`（排除 system、tool、common）
- ❌ 不统计：system、tool、common

**移动端**：
- ✅ 统计：`plus-uniapp/src/pages-sub/`（全部统计）
- ✅ 统计：`plus-uniapp/src/pages/*`（排除 index、login、user）
- ❌ 不统计：pages/index、pages/login、pages/user

## 💡 常见问题

### Q1: 我可以修改框架模块的代码吗？

**不建议**。框架模块是通用功能，修改后升级框架会有冲突。如果需要扩展，建议：
- 继承框架类并重写
- 在业务模块中封装
- 通过配置文件调整行为

### Q2: 如何添加新的系统管理功能？

如果是通用的系统功能（如新的监控、新的工具），可以考虑添加到 `ruoyi-system` 模块。
但如果是业务相关的功能，应该放到业务模块中。

### Q3: 代码生成器生成的代码是业务代码吗？

**是的**。代码生成器生成的代码是根据你的业务表生成的，属于业务代码。
生成的代码会放到你指定的业务模块中（如 `ruoyi-mall`）。

### Q4: 为什么我执行 /progress 显示 0%？

因为你还没有开发任何业务模块。框架模块不参与进度统计。
当你创建第一个业务模块后，进度就会开始统计。

## 🎯 总结

| 类型 | 框架模块（已完成） | 业务模块（需要开发） |
|------|------------------|-------------------|
| 后端 | ruoyi-common、ruoyi-admin、ruoyi-system、ruoyi-generator | ruoyi-modules/ruoyi-{你的业务}/ |
| 前端PC Views | views/system、views/tool、views/common | views/ 下除了框架目录外的所有目录（business/、mall/、iot/ 等） |
| 前端PC API | api/system、api/tool、api/common | api/ 下除了框架目录外的所有目录 |
| 移动端 | pages/index、pages/login、pages/user | pages/ 下除了框架页面外的页面 + pages-sub/ 全部 |
| 统计进度 | ❌ 不统计 | ✅ 只统计业务模块 |

**记住**：
- 框架 = 已完成的通用功能
- 业务 = 你要开发的项目功能
- 进度统计只看业务，不看框架
