# 新项目开发流程指南

> 基于 RuoYi-Plus-Uniapp 框架的标准开发流程

最后更新: 2025-12-05

---

## 🎯 核心理念

### 框架 ≠ 业务

| 类型 | 说明 | 是否统计进度 |
|------|------|------------|
| **框架代码** | 系统管理、代码生成器、通用工具库等 | ❌ 不统计（已完成） |
| **业务代码** | 你要开发的项目功能模块 | ✅ 只统计业务 |

**关键点**：
- 框架代码是**固定的**、**已完成的**，不需要重复扫描
- 进度统计**只看业务模块**，不看框架
- 全新项目进度是 **0%**，不是 100%

## 📁 项目结构速览

### 后端结构

```
ruoyi-modules/
├── ruoyi-system/          ❌ 框架（系统管理，29个功能）
├── ruoyi-generator/       ❌ 框架（代码生成器）
├── ruoyi-business/        ✅ 业务（示例，可删除或保留）
├── ruoyi-mall/            ✅ 业务（示例，可删除）
└── ruoyi-{你的业务}/      ✅ 创建你的业务模块
```

### 前端结构（PC端）

```
plus-ui/src/
├── views/
│   ├── system/            ❌ 框架（系统管理页面）
│   ├── tool/              ❌ 框架（工具页面）
│   ├── common/            ❌ 框架（通用页面）
│   ├── business/          ✅ 业务（基础业务页面）
│   ├── mall/              ✅ 业务（商城页面，如果有）
│   ├── iot/               ✅ 业务（IoT页面，如果有）
│   └── {你的模块}/        ✅ 业务（自定义业务页面）
└── api/
    ├── system/            ❌ 框架（系统API）
    ├── tool/              ❌ 框架（工具API）
    ├── common/            ❌ 框架（通用API）
    ├── business/          ✅ 业务（基础业务API）
    └── {你的模块}/        ✅ 业务（自定义业务API）
```

**规则**：views/ 和 api/ 下，除了 `system/`、`tool/`、`common/` 外，其他都是业务目录。

### 移动端结构

```
plus-uniapp/src/
├── pages/                 ⚠️ 混合（框架主包 + 业务主包）
│   ├── index/             ❌ 框架（首页）
│   ├── login/             ❌ 框架（登录）
│   ├── user/              ❌ 框架（个人中心）
│   └── {业务主包页面}/    ✅ 业务（如 home、goods 等）
└── pages-sub/             ✅ 业务（分包页面，全部是业务）
```

**规则**：pages/ 下只有 `index/`、`login/`、`user/` 是框架，其他都是业务；pages-sub/ 全部是业务。

## 🚀 标准开发流程

### 阶段 1: 项目初始化（第一次使用）

#### 1.1 克隆或创建项目

```bash
git clone <your-project-url>
cd ruoyi-plus-uniapp
```

#### 1.2 启动 Claude Code

```bash
# 打开项目
code .
# 或使用 Claude Code 直接打开
```

#### 1.3 查看项目状态

```bash
/start
```

**预期输出**（全新项目）：
```
👋 欢迎使用 RuoYi-Plus-Uniapp 框架

🎯 这是一个全新项目

框架状态: ✅ 已就绪
业务模块: ⏳ 尚未开发（检测到 0 个业务模块）

快速开始:
- 查看框架说明: .claude/docs/框架说明.md
- 开始开发: /dev 或 /crud
```

#### 1.4 了解框架（可选）

查看 `.claude/docs/框架说明.md` 了解：
- 哪些是框架模块（已完成）
- 哪些是业务开发区域（需要开发）
- 进度统计规则

---

### 阶段 2: 开发第一个业务功能

#### 方式 1: 使用代码生成器（推荐）

**步骤**：
1. 设计数据库表
2. 访问代码生成器页面（系统工具 → 代码生成）
3. 导入表
4. 配置生成选项：
   - 模块名：如 `ruoyi-mall`（商城）
   - 包路径：如 `plus.ruoyi.mall`
   - 业务名：如 `goods`（商品）
   - 表前缀：如 `m_`
5. 一键生成代码

**生成内容**：
- 后端：Entity、BO、VO、Controller、Service、DAO、Mapper
- 前端：Vue 页面、API 文件
- SQL：菜单数据

#### 方式 2: 使用 /dev 命令

```bash
/dev
```

**Claude 会引导你**：
1. 需求分析
2. 数据库设计
3. 后端代码生成
4. 前端页面生成
5. 测试和优化

#### 方式 3: 使用 /crud 命令（快速）

```bash
/crud
```

快速生成标准 CRUD 功能。

---

#### 3.1 查看详细进度

```bash
/progress
```

**输出示例**：


**输出示例**：
```

   - 建议使用框架的 ruoyi-common-pay 模块
```

---

### 阶段 4: 初始化文档（可选）

当你开发了一些业务功能后，可以初始化业务文档：

```bash
/init-docs
```

**会生成**：
- `docs/项目状态.md` - 业务进度统计
- `docs/需求文档.md` - 业务需求管理
- `docs/待办清单.md` - 业务 TODO 跟踪

**注意**：
- 只扫描业务模块，不扫描框架
- 如果是全新项目（0个业务模块），会生成空模板
- 开发业务功能后再次执行可更新文档

---

### 阶段 5: 持续开发循环

```
/start → 查看今天的状态
   ↓
/next → 获取开发建议
   ↓
/dev 或 /crud → 开发新功能
   ↓
/check → 代码规范检查
   ↓
/update-status → 更新进度（可选）
   ↓
git commit → 提交代码
   ↓
返回 /start（新的一天）
```

## 📋 常用命令速查

| 命令 | 用途 | 使用场景 |
|------|------|---------|
| `/start` | 查看项目状态 | 每天开始工作时 |
| `/dev` | 开发新功能 | 需要完整引导的功能开发 |
| `/crud` | 快速生成CRUD | 标准增删改查功能 |
| `/progress` | 查看详细进度 | 了解业务模块完成情况 |
| `/next` | 获取开发建议 | 不知道下一步做什么时 |

| `/update-status` | 更新进度 | 完成功能后更新文档 |
| `/check` | 代码规范检查 | 提交前检查代码质量 |

## 💡 最佳实践

### 1. 模块命名规范

**后端模块**：
- `ruoyi-mall` - 商城
- `ruoyi-iot` - 物联网
- `ruoyi-crm` - 客户管理
- `ruoyi-erp` - 企业资源
- `ruoyi-{你的业务}` - 自定义

**表前缀**：
- `m_` - mall（商城）
- `iot_` - iot（物联网）
- `crm_` - crm（客户管理）
- `b_` - business（基础业务）

### 2. 不要修改框架代码

**禁止修改**：
- `ruoyi-common/*` - 通用工具
- `ruoyi-admin` - 启动入口
- `ruoyi-modules/ruoyi-system` - 系统管理
- `ruoyi-modules/ruoyi-generator` - 代码生成器
- `plus-ui/src/views/system` - 系统页面
- `plus-ui/src/views/tool` - 工具页面

**原因**：
- 框架升级时会有冲突
- 影响其他项目的一致性

**如需扩展**：
- 继承框架类并重写
- 在业务模块中封装
- 通过配置文件调整

### 3. 合理使用代码生成器

**适合使用代码生成器**：
- 标准的 CRUD 功能
- 单表、树表、主子表
- 快速原型开发

**不适合使用代码生成器**：
- 复杂的业务逻辑
- 需要自定义的查询
- 特殊的数据处理

**生成后要做的**：
- 检查生成的代码
- 补充业务逻辑
- 优化查询性能
- 添加必要的注释

### 4. 保持文档同步

**何时更新文档**：
- 完成一个功能模块
- 修复重要 Bug
- 重构代码结构
- 项目里程碑

**如何更新**：
```bash
/update-status
```

或在 Git 提交时说明"完成了XXX功能"，会自动触发更新。

## 🤔 常见问题

### Q1: 为什么执行 /progress 显示 0%？

**答**：因为你还没有开发任何业务模块。框架模块不参与进度统计。
当你创建第一个业务模块后，进度就会开始统计。

### Q2: ruoyi-business 和 ruoyi-mall 是框架还是业务？

**答**：是**业务示例**。
- 如果你的项目需要这些功能，可以保留并修改
- 如果不需要，可以删除
- 它们会被统计到业务进度中

### Q3: 我可以在 ruoyi-system 中添加功能吗？

**不建议**。ruoyi-system 是系统管理模块，属于框架。
- 如果是通用的系统功能，考虑添加
- 如果是业务相关的功能，应该放到业务模块

### Q4: 如何判断哪些代码是框架、哪些是业务？

**参考配置文件**：`.claude/framework-config.json`

**简单判断**：
- 框架：系统管理、通用工具、代码生成器
- 业务：你的项目特定功能

**查看框架说明**：`.claude/docs/框架说明.md`

### Q5: /init-docs 和 /start 有什么区别？

| 命令 | 用途 | 生成内容 |
|------|------|---------|
| `/start` | 快速查看状态 | 屏幕输出 |
| `/init-docs` | 生成详细文档 | docs/ 目录下的 3 个文件 |

**建议**：
- 每天开始工作时用 `/start`
- 有业务代码后用 `/init-docs` 生成文档
- 之后用 `/update-status` 更新文档

## 🎯 总结

### 记住 3 个核心点

1. **框架 ≠ 业务**
   - 框架代码已完成，不参与进度统计
   - 只统计你开发的业务模块

2. **全新项目进度是 0%**
   - 不是 100%（那是框架完成度）
   - 开发业务功能后进度才会增长

3. **不要浪费资源扫描框架**
   - 所有命令都只扫描业务模块
   - 框架说明已预置，无需重复生成

### 开发流程总结

```
克隆项目 → /start 查看状态 → 开发业务功能 → /progress 查看进度 → git commit 提交代码
```
